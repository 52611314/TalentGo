## 安装与运行

先启动 Docker Desktop 引擎，再于根目录运行 `./scripts/setup.ps1`。需要 python、npm.cmd、docker；6543/8000/5173 不能被其他服务占用。脚本不会覆盖已有 .env；创建缺失配置与随机密码、安装依赖锁、启动 db、升级开发库并创建独立测试库（不重置已有测试数据）。首次需网络。

终端 A 执行 `./scripts/start-dev.ps1`，终端 B 执行 `./scripts/start-dev.ps1 -Service frontend`。访问 http://127.0.0.1:5173 ，API 文档 http://127.0.0.1:8000/docs 。面试入口已开放，固定 Mock 不代表真实能力评价。

已有 uv 时，手动命令如下；无全局 uv 时可用 .tools/bootstrap/Scripts/python.exe -m uv 替代。

```powershell
uv sync --project backend --frozen
uv run --project backend alembic -c backend/alembic.ini upgrade head
uv run --project backend python scripts/create_test_db.py
uv run --project backend uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

前端在 frontend 目录运行 npm ci 和 npm run dev。开发服务运行时不要重装 node_modules，先停止相应服务。

## 数据库与检查

PostgreSQL 宿主和容器实际端口均为 **6543**；数据库 talentgo、独立测试库 talentgo_test。Compose 只管理 db，卷 talentgo_talentgo_pgdata 保存资料。Docker 镜像附带的暴露端口元数据不是实际监听。

`./scripts/check.ps1` 执行 pytest、开发库 Alembic 差异检查及前端类型/生产构建。测试会清理专用 talentgo_test 的用户/资料/回执，不清理 talentgo。readiness 同时检查数据库可连接及迁移版本 0002_m2_interview；不是仅检查进程存活。

API 已注册 M1 基础和 M2 会话/操作端点；真实模型、记忆等后续接口没有以假成功方式暴露。

## 停止、备份与故障

开发终端 Ctrl+C 停止对应应用，docker compose stop db 停止数据库；恢复执行 docker compose up -d db 后启动应用。普通停止不会删卷，禁止把删卷作为密码故障处理手段。

start-dev.ps1 遇端口占用会拒绝启动，不停止无关进程。当前没有系统级安装、开机服务或整套应用容器化。

backup-db.ps1 将数据库导出到忽略的 database/backups/*.dump，密码不出现在参数中。脚本语法已检查，备份恢复全流程未验证；恢复必须用独立库，不能覆盖开发资料。

| 故障 | 检查 |
|---|---|
| Docker 连接失败 | Desktop 引擎与执行权限 |
| 数据库拒绝 | 实际端口 6543、.env 与已有卷的凭据是否一致 |
| SCHEMA_NOT_READY | 用 Alembic 升级，不用 create_all 绕过迁移 |
| 401 | 本机是否保存有效训练身份，首版不支持找回 |
| 保存 409 | 版本冲突时刷新并重新确认修改；不要覆盖他人变更 |
| 前端无连接 | 前后端进程、VITE_API_BASE_URL、CORS |

检查记录见 [M1 阶段报告](M1阶段报告.md)。
