# TalentGo 项目开发计划

版本：v0.2；更新：2026-11-13；当前 M0—M2 已完成，M3—M6 未开始。项目根目录 `D:\计算机前沿技术\hf\TalentGo`，远程仓库 https://github.com/52611314/TalentGo 。本文保留完整工作分解，不用里程碑表替代实施说明。

## 1. 项目目标与实施原则

TalentGo 面向准备软件开发实习、校招的计算机专业学生。目标是通过文字模拟面试，让用户明确训练目标、完成有上下文的问答、获得有证据的反馈，并依据长期薄弱点复练。首版提供前端和后端两个岗位方向，以及技术、行为、压力三种面试模式。

项目必须同时满足可用性、可解释性和课程验证要求。功能完成意味着可以实际操作、有正确的数据保存与失败处理、通过相应检查，并有与代码一致的说明；存在页面、空文件、Prompt 名称或设计图不等于功能已实现。

每次只实施用户指定的一个阶段。阶段结束时完成本地验证、打开本地展示、更新完整文档和阶段报告、正常提交并推送 GitHub，然后停止。未通过验收的项目保留真实状态，不提前进入下一阶段，也不编造测试或用户反馈。

## 2. 当前基础与范围约束

M1 已具备 Vue/TypeScript/Vite/Pinia 前端，FastAPI/Pydantic/SQLAlchemy 后端，PostgreSQL 数据库及 Alembic 首次迁移。匿名身份与资料保存已通过工程测试和浏览器验证。沿用这些已验证能力，不重建数据库或覆盖用户资料。

数据库固定为 PostgreSQL，监听和宿主映射端口均为 **6543**。开发库 talentgo，独立测试库 talentgo_test。源码、配置样例和依赖锁提交 Git；真实 .env、令牌、密码、虚拟环境、备份和运行产物不提交。

首版不包括语音、数字人、上传简历解析、在线代码执行、联网搜索、支付或招聘录用决策。用户直接填写背景和项目经历。公开部署、完整账号找回、多实例任务队列属于另行规划，不由本地演示自动推导完成。

M2 只用明确标记的确定性 Mock，不调用真实模型，也不生成貌似权威的能力分数。M3 才实现真实模型、Skill 和评分证据；M4 才实现长期记忆、成长趋势和复练。阶段边界防止用 Mock 结果冒充算法验证。

## 4. M0：需求与设计基线

### 4.2 完成与后续维护

M0 已完成。用户删除的 HANDOFF、独立测试/算法/试用记录等文档不自动恢复；当前执行事实集中在阶段报告，保留文档负责持续设计。需求、接口或数据库改变时必须同步相应说明，不能把旧设计一律改成“已实现”。

## 5. M1：可运行基础

### 5.1 已实施任务

建立忽略规则和本地随机密码配置；锁定并安装前后端依赖；实现 FastAPI 与 Vue 入口、健康接口、统一错误/request_id；创建匿名昵称身份并只保存令牌哈希；实现训练资料保存和读取；使用 version 防止并发覆盖、请求回执防重复提交；创建用户、资料、回执三张业务表及首次迁移；提供安装、启动、检查脚本。

### 5.2 已验证行为

前端类型与生产构建通过；15 项后端检查通过，覆盖身份隔离、无效/撤销令牌、输入边界、重复/并发请求、版本冲突和健康；专用测试库完成升级—降级—升级与差异检查；浏览器完成创建、编辑、保存与刷新。实际记录见 M1阶段报告，不将这些检查当作面试或模型效果验证。

## 6. M2：最小文字训练闭环（历史完成）

### 6.1 进入条件与目标

进入前核对 Git 工作区、保留文档、远程 M1 提交、本地数据库与端口。目标是在不依赖外部 Key 的情况下跑通完整产品流程，验证状态、消息、持久化、长操作和前端交互，为真实模型替换提供稳定边界。

用户完成一次训练应能：选择配置；缺少目标时接受必要澄清；启动并看到完整首题；提交回答并获得确定性的 Mock 追问或下一题；请求提示、跳过、暂停恢复或提前结束；查看本次真实问答覆盖与 Mock 总结；刷新页面继续读取同一会话。Mock 总结不含真实能力分数。

### 6.2 M2-A：数据结构与迁移

新增 interview_sessions、questions、messages、operations、operation_events、reports。会话保存用户归属、角色、模式、配置、画像快照、version 和当前题；题目保存主问题序号、状态、追问数；正式消息只保存完整已提交文本；操作保存请求输入引用、执行状态、attempt、取消标志及错误；事件保存单调序号以支持补发；报告保存 Mock 标识、覆盖统计和摘要。

设计并实现外键、会话/题目归属、唯一序号、同一会话至多一个活动操作、报告唯一性等约束。同步操作继续使用共享幂等回执，不能使不同 API 或同步/异步两条路径绕过同一身份的请求键冲突。增加第二个 Alembic 版本，不修改已使用的首个迁移。

验证空测试库升级、M1→M2 的非破坏升级、降级后重新升级、ORM 差异与约束。测试清理仅限专用测试库，迁移不得丢弃已有开发身份或档案。

### 6.3 M2-B：显式状态机

会话状态：clarifying、ready、interviewing、paused、evaluating、completed、aborted。操作状态独立为 queued、running、succeeded、failed、cancelled。前端不能根据显示的文字自行决定服务端状态。

创建缺岗位或模式的会话进入 clarifying；配置完整为 ready。开始成功提交首题才进入 interviewing；暂停只能在无活动操作时执行；结束进入 evaluating，报告与 completed 在同一最终事务提交。取消未开始的配置使用 aborted；提前结束已有面试使用 evaluating/completed 并披露覆盖不足。

每个修改校验 user、version、状态、当前题和幂等键。正在生成时第二条答案不能进入。压力模式开始前要求明确同意强度；M2 仅演示可控问答，不宣称已实现压力 Skill 或心理评价。

### 6.4 M2-C：配置与主动澄清

配置包括 role、mode、question_count（1—10）、difficulty（1—3）、max_followups（0—2）、pressure_level（1—3）和 pressure_consent。配置页可从当前画像提供用户可修改的默认值，但不偷偷替缺失意图下结论。

澄清采用确定性字段识别与选项，引导补足岗位/类型；信息完整时不重复询问。澄清作为会话消息保存，提供按钮选项以避免用户在固定 Mock 中猜关键词。M3 再扩展自然语言理解，M2 不声称具备泛化意图识别。

### 6.5 M2-D：Mock 提问与消息

Mock 适配器按岗位和模式给出固定题目，按明确长度/轮次等演示规则决定是否追问；记录规则含义，不能包装为真实语义评估。题目数量可超过固定样例时采用不同题号/主题组合，避免同场反复使用同一主问题。

先保存用户答案并创建操作，再在短事务外生成；只在最终成功提交时保存完整助手问题、切换当前题和递增状态。临时流片段不能成为可作答问题。重试失败操作复用已保存输入，不再新增同一条用户答案。提示使用与跳过要能在消息/覆盖中核对。

### 6.6 M2-E：操作、事件和恢复

新增操作查询、取消和重试。单实例应用内执行器负责生成，PostgreSQL 保存任务事实；不宣称等同可靠分布式队列。进程中断后把未完成操作标成明确失败，再允许重试，不假装接续模型内部生成。

SSE 订阅只读取事件，不触发生成。事件有 operation_id、attempt_no 和递增 seq，先持久化再发送；客户端按 ID 去重并支持 Last-Event-ID 补发。断流与取消分离：浏览器重新订阅原操作，停止按钮才请求取消。取消与成功竞争由数据库终态决定，迟到结果不得覆盖已取消状态。

客户端刷新读取服务端当前会话、正式消息与活动/最近操作。恢复时不自动重发答案。网络不确定时保留请求键和正文以便幂等重试。显示“已保存”“生成中”“生成失败/取消”“可重试”等不同状态。

### 6.7 M2-F：界面与报告

增加配置页、面试室、历史列表和 Mock 总结页，延续 M1 的视觉与身份机制。面试室包含消息、输入、进度、当前题、操作状态、提示/跳过/暂停/结束、停止与重试。切换身份或路由时撤销旧订阅并清除旧视图，防止前一身份的迟到响应出现在新身份页面。

报告展示计划题数、已答题数、跳过/未到达、回答与追问记录，以及明确的 Mock 提醒。总分为 null，不显示雷达能力图或虚假提升。历史只读当前身份数据，支持重新进入未完成会话。空状态和故障应有可执行的下一步，不只显示失败。

### 6.8 M2-G：验证与退出标准

必须验证：完整主答闭环；缺项澄清与已知配置不重复澄清；固定追问预算；提示/跳过；暂停/恢复；提前结束与无答案报告；同键重放与异键并发；旧版本冲突；跨用户会话/消息/操作/事件/报告隔离；取消与重试不重复写入；事件补发/非法游标；进程中断后的明确失败与可恢复输入；迁移与 M1 回归。

浏览器实际完成至少一次配置—问答—结束—报告，验证刷新恢复；前端 build/typecheck 与后端规则/集成测试通过。关键路径失败必须修复后再演示，暂未验证的边界写清局限。阶段报告记录实际数量与结果、截图、源码提交和已知限制；检查秘密和工作区后正常推送，核对远端 SHA。最后停在 M2。

## 7. M3：真实模型与四个 Skill

### 7.1 进入条件

M2 的状态、数据、任务和 UI 闭环稳定，已有可复现测试。用户明确继续 M3，且真实模型配置通过安全环境提供；不要求把 Key 发进聊天，不因没有 Key 而编造模型结果。

### 7.2 实施任务

实现统一模型适配接口与 DeepSeek HTTP 客户端，配置模型名称、超时、输出预算、错误类型和用量记录。确定性 Mock 保留为工程测试通道，但界面、数据和导出始终标记来源。

实现 technical、behavioral、pressure、review 四 Skill。每个具备独立触发、输入输出、执行逻辑、领域知识、Prompt/rubric 版本和案例；不是仅设置四个名称。技术面关注概念、原理、边界与项目取舍；行为面提取 STAR 缺项并澄清贡献；压力面基于已有回答提出建设性质疑且允许降低强度；复盘面形成证据对应的建议。

增加评价实体与迁移。五维 0—5 分及模式权重按 Skill与评分设计 实现，总分由后端 Decimal 计算。校验维度、范围、证据 message_id 归属与 quote 原文；结构错误允许一次受控修复，仍失败不计分。主答与追问组成一个最终主问题评价，不能重复计权。

先由程序汇总有效数值和覆盖，再生成报告文字；用户不能通过回答中的“给满分”修改规则。跳过、未到达、模型未评排除有效均值并披露覆盖；材料不足显示 null。报告保留模型、Prompt、rubric 与来源版本。

### 7.3 本轮实际落地与待验收

M3 已实现 DeepSeek 真实适配、自然语言澄清、四 Skill 与 40 个种子题、五维结构与原文校验、一次受控修复、后端算分、单题 provisional/final、难度/追问/提示、报告原文定位与运行记录。已完成三类真实一题闭环、固定输入重复与单条注入探索；详细数值、工程检查与截图见 M3阶段报告。Mock 继续独立保留。数据库升级到 0003_m3_skills，密钥不入库、不入 Git。

建立 13 个作者合成的优/中/差/不足与注入样本，参考点来自当前种子锚点。level_intent 不是人评真值，human_reviews 仍为空。原定两名独立人工评阅因工作量被用户明确取消，改由模型辅助评估；真实人工校准仍未执行，模型间差异不充当人评 MAE。该变更由用户授权进入 M4，不隐去验证局限。没有真实用户试用或客观准确率结论。

### 7.4 验证与退出

工程验证覆盖校验失败、超时、限额、取消、注入材料和引用错误。建立固定优/中/差/不足样本，与至少两名人工评阅者对照，记录分歧、每维误差与严重错判；重复相同输入检查波动。样本不足时只报告探索结果，不能声称准确无偏。

三类面试与四 Skill 能实际演示，真实模型与 Mock 分开验收；M1/M2 回归通过；界面无真实经历核实、心理状态诊断或录用概率承诺。阶段报告、文档、截图和提交齐全后停止。

## 8. M4：长期记忆、摘要与针对性复练

### 8.1 进入条件

M3 已产生结构化有效评价和可追溯来源，评分版本已固定。当前画像、会话快照与用户消息能够清楚区分。

### 8.2 实施任务

新增 memories、memory_usages、session_summaries、practice_tasks 等实体。长期记忆按目标、偏好、弱项组织，带 user、来源、确认状态、version 和更新时间。用户明确提供与系统推断分别记录；推断默认关闭，启用后也不覆盖已确认冲突事实。

实现结构化检索、冲突处理和预算裁剪：系统规则→Skill→画像→相关记忆→摘要→最近消息→当前输入。首版无需向量库，记录实际注入条目的 ID/版本/原因，不记录内部思维链。当前题完整线程优先保留，超限不静默截断后正常评分。

实现查看、确认、纠正和删除。每次变更递增 memory_revision，失效摘要和上下文缓存；运行结果提交前核对版本，防止删除期间旧结果重新写入。历史报告不自动重算，但新请求不能经旧摘要读回已删除记忆。

从有效评价生成具体复练任务，关联原题/评价/弱项；新会话带入任务主题并在实际有效完成后更新状态。成长趋势按岗位、mode、rubric_version 分组，跨版本并排标注，不误作同尺度提升。

### 8.3 本轮具体实施

新增记忆 CRUD、确认/纠正、结构化筛选与最多八条注入；保存实际 usage 元数据；画像更新和记忆变更统一递增 revision、失效摘要并拦截旧模型结果。无内容的回执/删除轨迹避免从缓存找回已删记忆。摘要使用确定性主题覆盖和数值，不额外调用模型，也不复制可删除记忆正文。当前题保持完整。

从真实非空 final 的缺口派生复练，首题注入来源锚点；后续题排除已用来源。任务在真实复练成功结束且首题有有效评价后完成，跳过/无答案/仅打开不完成。来源删除采用级联清推断/任务、子会话来源置空，保留既有报告。趋势按岗位/模式/rubric 分组，模型、Prompt、覆盖并列展示，不自动声称提升。页面提供记忆管理、来源任务、分组记录和注入追踪。

### 8.4 验证与退出

跨会话明确读取偏好/弱项，修改删除后不再注入，关闭推断不自动写入；两身份相同主题检索严格隔离；压缩前后当前题证据保持；任务完成不能仅因打开页面触发；来源会话删除按既定策略处理。实际演示“上次发现缺口→下次改变训练→复查结果”，更新报告后停止。

## 9. M5：场景回归、异常完善与体验

### 9.1 测试集合

填充 30 个对话场景：技术 8、行为 6、压力 4、澄清/记忆 8、边界 4。每个案例包括前置、输入轮次、预期行为、实际、代码与模型/Prompt/rubric 版本、证据与状态。异常场景族的分支分别展开，不用单条通过掩盖未执行分支。

主要内容包括正确/错误/模糊/不会/跑题回答、STAR 缺项、矛盾叙述、压力降级退出、缺项澄清、跨会话记忆、纠正删除、长历史、超时/断流/重启、畸形输出、重复/并发提交和提示注入。工程 Mock、真实模型、人审三类结果分别记录。

### 9.2 体验与可靠性

检查键盘访问、输入草稿、移动与桌面布局、流状态、错误重试、空状态、导出、用户切换和路由离开。评分图提供文字结果，状态不只靠颜色。修复观测到的缺陷，不为了检查数量写机械测试。

固定环境测量首事件、首字、完成时延、失败类型与 token 用量；未返回用量为 null。样本足够才报告 p50/p95；费用依据实际调用日期和价格核算，不预先承诺时延、并发、成本或提升幅度。

### 9.3 退出

P0 需求映射到实现和证据；越权、资料丢失、取消误成功、错误高分、记忆删除回流等重大缺陷关闭。其余限制有明确影响、复现和后续安排。回归结果、文档、演示与源码一致后停止。

## 10. M6：真实用户验证与课程材料

### 10.1 真实参与

### 10.2 报告与演示

### 10.3 退出

至少四名真实用户记录可核对，反馈授权明确；测试数据与结论无混淆；报告和演示能够由现有源码复现；依赖锁、启动文档、迁移、阶段报告和远程提交齐全。是否提交课程平台由用户决定，不自动发送给他人。

## 12. 质量门槛与风险处理

| 风险 | 预防与处理 | 必须验证的证据 |
|---|---|---|
| 已保存答案丢失 | 先持久化输入，长调用在事务外，重试复用引用 | 刷新、取消、重启后输入仍在 |
| 重复/并发写入 | 身份内共享幂等、会话 version、活动操作唯一约束 | 同键回放、异键冲突、唯一终态 |
| 任务中断假成功 | 状态/事件持久化，单实例约束，启动时标失败 | 中断记录和显式重试 |
| 越权读取 | 所有路径按服务端身份过滤，组合归属检查 | A/B 跨资源请求与事件订阅 |
| 模型坏输出 | Schema/引用校验，一次修复，失败不计分 | 坏 JSON、越界分和伪造证据 |
| 记忆污染/回流 | 来源确认、revision、摘要失效与提交前核对 | 删除、冲突、并发修改 |
| 端口或数据库误用 | 6543 统一，测试库名称/归属检查 | 实际 SHOW port 与隔离 |
| 秘密上传 | .gitignore、暂存清单、私密值扫描 | 提交前检查，不输出凭证 |
| 范围膨胀 | 以本阶段目标为准，扩展延后 | 阶段报告明确未实现项 |
| 没有真实反馈 | 稳定版本后实际组织，不生成替代 | 四人实际记录与授权 |
