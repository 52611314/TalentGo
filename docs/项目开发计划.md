## 2. 建议任务顺序

1. 先完成不涉及业务的环境与迁移，确认 PostgreSQL 的实际监听端口为 6543。
2. 实现文档约定的身份创建幂等例外、version、错误与 SSE 契约，再连接前端页面。
3. 用确定性 Mock 打通状态、保存、恢复与评分计算，减少边调模型边调流程的混乱。
4. 引入真实模型并验证解析、引用、超时和取消；不把模型建议直接当数据库操作。
5. 建立每个 Skill 的知识锚点与案例，然后实现记忆和复练。
6. 增加图表、趋势与运行记录，形成可演示体验；按实际缺陷补测试，不机械扩大测试数量。

## 3. 实施前必须实现的文件

| 批次 | 文件类型 | 说明 |
|---|---|---|
| 基础保护 | .gitignore、各 .env.example | 先排除秘密和产物，样例只放占位值 |
| 依赖构建 | frontend/package.json、tsconfig、vite；backend/pyproject | 验证兼容版本并创建真实锁文件 |
| 服务数据 | main、config、db、models、Alembic | 空库初始化可复现 |
| 契约验证 | schemas、identity、health、测试夹具 | 权限、错误和数据库隔离先建立 |
| 业务与 UI | services、agent、routes、views | 按功能映射逐步实现 |

不使用空配置文件“安装成功”作为完成证据。不得在当前阶段随手填入 TODO 代码越过用户边界。

## 4. 质量门槛

- 每个 P0 需求有实际代码、适当验证和文档一致性检查。
- 数据迁移在独立 PostgreSQL 测试库执行，约束、事务和删除行为可复现。
- 关键规则测试覆盖评分计算、状态转换、幂等、并发、记忆隔离和删除后读写。
- 真实模型评测记录模型名称、提示词/评分标准版本、输入、结果和失败；无 Key 时不得填“通过”。
- 任一重大越权、密钥泄露、答案丢失、错误高分或中断误报成功都阻止进入真实用户阶段。
- 每阶段实际执行后更新对应阶段报告与开发计划，不沿用设计阶段“未实现”标识，也不提前标为完成。

## 5. 风险与应对

| 风险 | 应对 | 验证 |
|---|---|---|
| 模型输出不稳定 | Schema 校验、一次修复、无效不计分 | 畸形结构/伪造证据案例 |
| 评分波动 | 题目锚点、固定版本、人工校准 | 重复性与一致性评测 |
| 生成中断 | 操作持久化、租约、明确失败和重试 | 断流/进程重启案例 |
| 数据混用 | 后端身份过滤、组合约束 | 两身份交叉访问 |
| 记忆错误或过期 | 来源、确认、纠正、版本与摘要失效 | 删除/冲突记忆案例 |
| 数据库端口误配 | 服务监听/映射/URL/健康检查均 6543 | 本机与容器分别连通检查 |
| 范围膨胀 | 先文字闭环，语音/数字人/代码执行延后 | 里程碑范围审查 |
| 用户测试未落实 | 可用版本后安排至少四人 | 实际匿名反馈与参与核对 |
