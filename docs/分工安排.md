# 分工安排

设计基线 v0.1，2026-11-13。用户尚未提供团队人数与成员，因此以角色分工，不虚构姓名、贡献比例或既有工作。单人实施可兼任全部开发角色。本轮未委派子代理。

## 1. 角色职责

| 角色 | 主要职责 | 主要位置 | 交接材料 |
|---|---|---|---|
| 需求与项目负责人 | 范围、课程要求、里程碑、验收 | docs/项目文档、开发计划 | 需求变更、验收结论 |
| 前端开发 | 页面、表单、流式交互、图表、恢复 | frontend/src | 页面流程、类型契约、浏览器验证 |
| 后端开发 | 身份、API、用例、状态、操作任务 | backend/app/api、services、core | API、错误和幂等记录 |
| Agent/知识开发 | Skill、Prompt、题库、评分锚点、记忆策略 | backend/app/agent、knowledge、llm | 版本、输入输出和案例 |
| 数据与环境 | 模型、迁移、6543 配置、备份与独立测试库 | database、backend/app/db、models、scripts | 迁移验证、环境说明 |
| 测试与文档 | 场景、回归、证据归档、文档一致性 | tests、docs | 实际结果、缺陷与复测 |
| 真实测试组织者 | 邀请参与者、说明用途、核对反馈 | 后续测试组织 | 至少四名真实用户的匿名化记录 |

开发角色承担设计和实现，不将“邀请真实用户、取得真实反馈”交由模拟身份完成。用户作为项目负责人决定范围与课程提交安排。

## 2. 协作顺序

后端与前端先共同审阅接口文档；数据库与后端共同确认约束；Agent 提供结构化契约后接入用例；测试根据需求验收行为而非照抄内部实现。允许按角色分工，但本轮不自动开启多代理或额外任务。

## 3. 模块交接约定

- 前端收到 API 字段、状态、错误码、示例及 Mock 标识后实现，不等待真实模型可用才调界面。
- Agent 交付 Skill 时同时说明触发、来源、输出 Schema、失败行为、版本及至少一个正例/反例。
- 数据结构变更必须带迁移、删除策略和对已有资料的影响；不能只改 ORM。
- 测试交付必须区分“未执行、通过、失败、阻塞”；截图与日志有来源，不能复用其他项目。
- 文档维护由改动者负责，复核者检查跨文档与路径一致性。

## 4. 当前工作归属

本轮执行 M4 记忆、摘要、复练和分组记录；用户取消双人人评，改由 Codex 作者参照与实际 DeepSeek 输出做辅助评估。该结果明确不是人评或真实用户试用，见 M4阶段报告。团队成员尚未指定，真实用户测试尚未发生，不预先填入贡献比例或试用结论。后续有成员名单后可在本文新增“成员—角色—任务—证据”表。
