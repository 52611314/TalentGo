# 登录修复与独立账号页面

日期：2026-11-17。基于现有 v0.6.0 的问题修复，未开展 M6 真人测试。

## 1. 登录失败原因和处理

用户的 Edge 请求携带 DNT: 1。旧前端默认跨域访问 127.0.0.1:8000，浏览器因此先发送 OPTIONS；后端原 allow_headers 中缺少 DNT，导致请求在预检阶段被拒绝，尚未执行账号密码校验。截图中的 400 与此配置一致。

本轮后端明确允许 DNT，保留已有来源、方法和其他请求头白名单，未知来源继续拒绝。前端默认 API_BASE、环境样例和首次配置脚本改为 /api/v1，由 Vite 开发/preview 将 /api 转发到 8000；流式事件和报告导出也沿用共享 API_BASE。本机忽略文件 frontend/.env 已同步调整。显式跨域配置仍可使用并受白名单约束。

实际本地 OPTIONS 携带 content-type,dnt 已返回 200；通过 5173 同源代理使用默认测试账号登录返回 200，退出返回 204。修复 CORS 必须重启后端，代理配置及环境文件变化需要重启前端；本轮验证时已加载新配置。

## 2. 独立页面与访问流程

- /login：独立登录页面，提供账号、密码及注册入口。
- /register：独立注册页面，注册成功进入工作空间。
- 未登录访问业务页面：跳转登录并记录原站内路径，成功后返回；外部地址和认证页自身不能作为返回目标。
- 刷新：先校验一次本浏览器缓存凭证，再决定是否进入业务页，避免业务布局闪现与重复校验。
- 凭证失效：转回登录，数据库账号不删除。退出也回到独立登录页。
- 工作空间账号弹窗：只保留当前账号说明和退出操作，不再包含注册或登录表单。

页面采用已有五级白紫渐变，左侧为产品介绍，右侧为登录/注册表单，覆盖 PC 范围。密码不写入浏览器存储；注册账号和登录凭证由服务端签发。浏览器禁止 localStorage 时仍可完成当前内存会话，不将已成功的服务端登录误报为失败。

## 3. 数据到底保存多久

users 存账号和随机盐口令哈希，profiles 存资料，训练相关表存问答与报告，这些表没有七天删除规则。注册事务已经实际提交到 PostgreSQL，正常服务重启不会清空它们；既有 Docker 命名卷继续保留。本轮无需新迁移，head=0005_accounts_roles，端口仍为 6543。

七天只对应 auth_sessions.expires_at。到期后旧 token 无效，重新输入账号密码会为同一 user_id 生成新凭证；退出、删除过期登录行都不会反向删除用户。页面已明确写明“账号与训练记录持久保存在数据库中”，避免将会话期限误解为账号寿命。

新集成测试将测试账号创建时间设为三十天前，提交目标资料，令 token 过期并清理其登录行，再在新事务中验证原密码、相同 user_id、创建时间和资料均保留。这是独立测试库中的受控时间场景，不冒充实际经过三十天的观察。

另外通过真实 5173 代理注册一个合成测试账号，独立 PostgreSQL 事务读取并确认口令哈希和目标已提交，退出后以原密码登录，验证同一用户及资料恢复；测试登录凭证已撤销，测试账号保留。没有把这些操作计作真人试用。

## 4. 用户指定删除项

删除首页“空间运行状态”卡片，以及该页面发起的健康检查请求和状态变量。练习方向区域扩展为整行，避免留下空列。后端健康接口继续服务启动与工程检查，不出现在这个首页组件中。

## 6. 手动体验

启动 Docker Desktop，根目录执行 docker compose up -d db；两个终端分别启动 scripts/start-dev.ps1 与 scripts/start-dev.ps1 -Service frontend。打开 http://127.0.0.1:5173/login 。默认普通测试账号仍为 admin/password；也可在 /register 创建自己的账号。旧登录有效时会自动进入工作台，先从右上角账号菜单退出即可查看独立登录页。
