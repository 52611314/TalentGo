# 接口文档

## M2 已实现范围与当前差异

2026-11-13：在 M1 六端点上新增 sessions 的创建/列表/读取/修改/删除、messages 的列表/提交、actions、Mock report，以及 operations 的查询/取消/重试/SSE。以运行中的 OpenAPI 为当前事实。下文记忆、trace、报告单独重试/导出、成长趋势、复练与反馈仍是未来契约，未注册。

当前模型来源固定 mock。创建会话不接收 source_task_id；配置 PATCH 是完整配置对象（未提供的子项应用默认值），只允许开始前；列表 status 为可选字符串筛选。消息用游标分页。DELETE /sessions/{id} 的 expected_version 是查询参数并要求幂等键。

取消/重试使用 POST /operations/{id}/cancel 与 /retry，无请求正文，仍要求身份和幂等键。失败报告通过原操作 retry，不另建报告任务。所有身份内修改共享回执命名空间；同键不同路径或内容返回 409。开始压力模式前缺确认返回 PRESSURE_CONSENT_REQUIRED；题目不符 QUESTION_MISMATCH；未处理的已保存答案要求 OPERATION_RETRY_REQUIRED；每题只允许一次成功提示 HINT_ALREADY_USED。

M2 报告返回 is_mock=true、total_score=null、dimension_scores={}、summary、coverage 和完整 messages，不返回真实评价。coverage 为 planned/asked/answered/skipped/not_reached/scored（固定 0）；answered 与 skipped 可重叠，因为曾回答后再跳过也须如实记录。

SSE 游标格式 operation_uuid:seq；非法或越界返回 INVALID_EVENT_CURSOR（400），终结超过七天返回 EVENT_HISTORY_EXPIRED（410）。当前只限制重放期，尚未实现定时物理清理。GET 只读取，不启动或重试任务。单实例执行器重启时将未完成任务标 PROCESS_INTERRUPTED，原输入保留、显式重试。


版本：API 设计 v1 / 文档基线 v0.1；日期：2026-11-13。**M1 基础接口和 M2 会话/操作接口均已实现；详见上方 M2 范围。** OpenAPI 位于 http://127.0.0.1:8000/docs 。只有上方未列入 M2 的扩展接口属于后续契约。M1 的请求键限制为字母/数字/下划线/短横线；角色与经验可显式清空，其他资料字段不可为 null。

## 1. 通用约定

- 根路径 `/api/v1`，本地后端目标 `http://localhost:8000`；数据库 PostgreSQL 端口 6543，不是 HTTP API 端口。
- JSON 使用 UTF-8；字段 snake_case；ID 是 UUID 字符串；时间为 ISO 8601 UTC。
- 除健康和创建身份外，必须 `Authorization: Bearer <token>`。token 只在创建身份时完整返回一次，不能写日志。
- 所有修改请求必须提供 `Idempotency-Key`（1—80 字符）。创建身份允许无 token，但请求键须为浏览器生成的至少 256 位随机值；后端保存其哈希并唯一约束。签发 token 仅返回一次，同键再次签发返回 409 IDENTITY_ALREADY_CREATED，不重发凭证。首次响应丢失且本机没有 token 时需显式新建身份，不承诺恢复旧身份。
- 涉及会话修改还带 `expected_version`；版本过期、忙碌、状态不允许均返回 409。请求中的 user_id 一律不作为身份来源。
- 列表使用 limit（默认 20，最大 100）与不透明 cursor，按 created_at/id 稳定排序；响应 `items`、`next_cursor`。
- 禁止未知输入字段；答案最多 8000 字符，背景/目标各 4000 字符，记忆正文 1000 字符，反馈 2000 字符。过长返回 422。

成功示意：`{"data":{"id":"<uuid>"},"request_id":"<uuid>"}`。分页内容位于 data。异步操作返回 202 和 operation_id，不在 HTTP 请求内假装已完成。

错误示意：`{"error":{"code":"SESSION_BUSY","message":"当前生成尚未结束","details":{}},"request_id":"<uuid>"}`。不回传栈、连接串、密钥或供应商原始敏感内容。

| HTTP | code 示例 | 语义 |
|---|---|---|
| 400 | INVALID_CURSOR | 请求语义或游标错误 |
| 401 | INVALID_IDENTITY | 缺失、无效或撤销身份 |
| 404 | RESOURCE_NOT_FOUND | 不存在或不属于当前用户 |
| 409 | VERSION_CONFLICT / SESSION_BUSY / INVALID_STATE / IDEMPOTENCY_CONFLICT | 状态、并发或重复键冲突 |
| 410 | EVENT_HISTORY_EXPIRED | 事件已清理，读取状态快照 |
| 422 | VALIDATION_ERROR | 参数结构、范围、必需字段错误 |
| 429 | RATE_LIMITED | 达到应用调用上限，后续实现 |
| 503 | MODEL_UNAVAILABLE / DATABASE_UNAVAILABLE | 服务依赖不可用 |

长操作在受理后失败，由 operations.status/error_code 和终结事件表达，不能再改已发送的 202 状态。

## 2. 健康、身份与资料

| 方法 | 路径 | 请求/查询 | 返回 |
|---|---|---|---|
| GET | /health/live | 无 | 进程存活，不访问外部模型 |
| GET | /health/ready | 无 | 数据库可连接及配置完整性；失败 503 |
| POST | /identity | display_name | 201：user_id、token、profile；不得因重放泄露他人凭证 |
| GET | /identity/me | 无 | 当前昵称、身份状态 |
| GET | /profile | 无 | 画像字段、version |
| PATCH | /profile | expected_version、待改字段 | 更新画像与新 version |

画像字段：target_role（frontend/backend/null）、experience_level（beginner/intern/graduate/null）、tech_stack（≤20 项）、background、goals、feedback_style（concise/detailed/guided）、allow_inferred_memory（默认 false）。变更当前画像不改已开始会话快照，但纠正/删除记忆需要使后续上下文缓存失效。

## 3. 面试会话

| 方法 | 路径 | 输入 | 返回 |
|---|---|---|---|
| POST | /sessions | title?、role?、mode?、config?、source_task_id? | 201：会话；信息不足 clarifying，否则 ready |
| GET | /sessions | status?、mode?、分页 | 当前用户的列表 |
| GET | /sessions/{id} | 无 | 状态、version、配置、当前题、覆盖计数、active_operation_id? |
| PATCH | /sessions/{id} | expected_version、title?/role?/mode?/config? | 仅 clarifying/ready 可编辑训练配置 |
| GET | /sessions/{id}/messages | 分页 | 正式完整消息，含 seq/question_id/kind |
| POST | /sessions/{id}/messages | expected_version、kind、content、question_id? | 202：operation_id、status、session_version |
| POST | /sessions/{id}/actions | expected_version、action、pressure_level? | 同步 200 或生成操作 202 |
| GET | /sessions/{id}/trace | 分页 | Skill、状态、记忆 ID/版本、耗时等脱敏元数据 |
| DELETE | /sessions/{id} | expected_version | 204；有运行操作先返回 409 |

config：question_count 默认 5、范围 1—10；difficulty 默认 1、范围 1—3；max_followups 默认 1、范围 0—2；pressure_level 默认 1、范围 1—3；pressure_consent 默认 false，只有压力模式开始前必须为 true。

messages.kind 仅 `clarification` 或 `answer`。clarification 只允许 clarifying，回答当前待确认字段；answer 只允许 interviewing，question_id 必填且必须为当前题。有未完成操作则拒绝；一次最多提出两个澄清点，同一字段不重复追问超过两次，仍缺信息时提供可选项，不替用户擅自确定目标。

actions：

| action | 条件 | 行为与响应 |
|---|---|---|
| clarify | clarifying 且空闲 | 202，生成澄清问题；GET 不触发模型 |
| start | ready，配置完整 | 202，生成首题；提交成功后进入 interviewing |
| hint | interviewing，当前题存在 | 202，生成提示，记录已用提示 |
| skip | interviewing，当前题存在 | 202，当前题标 skipped、生成下一题或进入复盘 |
| pause | interviewing 且空闲 | 200，状态 paused；忙碌时先停止生成 |
| resume | paused | 200，状态 interviewing；若无当前题，提示重试失败操作 |
| lower_pressure | interviewing/paused 且 mode=pressure、空闲 | 200，pressure_level 仅可下调 |
| finish | interviewing/paused 且空闲 | 202，结束并生成报告，状态 evaluating |
| abort | clarifying/ready 且空闲 | 200，aborted，不生成成绩 |

答案已保存但下一题生成失败时，当前题不切换，界面显示失败操作并提供 retry；不能要求重新 POST 同一答案。最后一题结束可以在同一操作内衔接复盘，或通过 finish 创建操作；最终报告只保存一次。

## 4. 长操作、取消与 SSE

| 方法 | 路径 | 行为 |
|---|---|---|
| GET | /operations/{id} | 状态、attempt_no、last_event_seq、result_refs、error、可重试性 |
| POST | /operations/{id}/cancel | 请求取消；已成功返回终态且不回滚；非终态由执行器确认 cancelled |
| POST | /operations/{id}/retry | 仅 failed/cancelled 且会话条件仍有效；重用输入引用，attempt_no＋1，202 |
| GET | /operations/{id}/events | text/event-stream，只订阅、不启动操作 |

操作任务是业务事实，订阅可多次连接。第一次读取无 Last-Event-ID 时从 seq=1 开始；重连携带上次 ID，如 `<operation_uuid>:12`。服务检查 ID 所属操作与 seq，按序补发持久化事件。已结束且事件完整重放后关闭连接；过期返回 410。

```text
id: <operation_uuid>:1
event: operation.started
data: {"operation_id":"<uuid>","attempt_no":1}

id: <operation_uuid>:2
event: text.delta
data: {"channel":"question","text":"请介绍","attempt_no":1}

id: <operation_uuid>:3
event: operation.succeeded
data: {"session_id":"<uuid>","session_version":4,"result_refs":{}}
```

其余事件：state.changed、operation.failed（error_code、retryable）、operation.cancelled。每 15 秒可发无业务序号的心跳注释；不是持久化数据。客户端按 seq 去重；attempt_no 变化清空临时输出。text.delta 是候选文本，只有成功事件后重新读取的正式消息可参与回答。错误时保留“生成中断”标识，不把残片写成新问题。

取消接口需立即显示“正在停止”；只有确认 cancelled 后释放会话占用。底层模型请求尽力取消，迟到返回不得写入正式结果。重试前检查旧操作无有效租约。后台进程中断后标记 PROCESS_INTERRUPTED，不能凭借数据库存有操作就声称实现持久任务恢复。

## 5. 记忆

| 方法 | 路径 | 输入/结果 |
|---|---|---|
| GET | /memories | kind?、topic?、分页 → 当前用户条目 |
| POST | /memories | kind、topic、content → 201，user_explicit、confirmed=true |
| PATCH | /memories/{id} | expected_version、content?/topic?/confirmed? → 新 version |
| DELETE | /memories/{id} | expected_version → 204，硬删除 |

响应含 id、kind、topic、content、source_type、source_session_id?、source_message_id?、source_evaluation_id?、confirmed、version、updated_at。客户端不能伪造 system_inferred 或来源 ID。弱项系统归纳仅在用户启用 allow_inferred_memory 后写入。编辑/删除使相关摘要失效，下一次上下文重新构造。历史报告不会自动改写，读取轨迹只保留 ID/版本而不复制已删除正文。

## 6. 报告、成长与复练

| 方法 | 路径 | 输入/结果 |
|---|---|---|
| GET | /sessions/{id}/report | pending/generating/failed 返回状态；ready 返回报告及评价 |
| POST | /sessions/{id}/report/retry | expected_version；仅 evaluating 且报告失败，202 |
| GET | /reports/trends | mode?、role?、rubric_version?、分页；不同版本分组 |
| GET | /sessions/{id}/report/export | format=markdown/json；仅 ready，附件响应 |
| GET | /practice-tasks | status?、分页 |
| GET | /practice-tasks/{id} | 任务及来源证据引用 |

报告响应：session_id、is_mock、rubric_version、prompt_version、dimension_scores、weights、total_score（可空）、coverage、strengths、gaps、recommendations、question_evaluations、practice_task_ids。每题评价含有效维度分、reason、evidence（message_id/quote/dimension）、missing_points、suggestion、提示使用情况。

复练通过 POST /sessions 的 source_task_id 发起，后端校验归属并带入任务主题、岗位和 mode。任务状态随新会话创建和有效完成自动改变。中止复练不自动判为完成；首版无需额外手工标完成接口。

## 7. 反馈

POST /feedback：session_id?、ratings（relevance/coherence/actionability/usability/reuse 均为 1—5 整数）、comment、consent_to_course_analysis、allow_quote；201 返回 id/created_at。GET /feedback 返回当前用户本人反馈，支持分页。关联会话必须属于本人。

课程报告仅统计 consent_to_course_analysis=true 的反馈；引用原话还需 allow_quote=true。不在普通 API 暴露全体用户反馈列表或原始身份数据。真实用户数量由实际测试记录核对，不根据 Mock 身份数量推算。

## 8. 幂等、并发与版本

除首次身份签发的明确例外，同一身份＋同一幂等键＋相同请求返回原资源/操作；同键不同内容 409。token 首次签发重放仅返回 IDENTITY_ALREADY_CREATED，不通用缓存明文令牌；创建键也不得进入访问日志。其余幂等记录覆盖请求方法、规范化路径和正文哈希。客户端按用户操作生成键，网络重发沿用，真正的新操作换键。

每个会话同时最多一个 queued/running 生成操作；第二条答案返回 SESSION_BUSY。资源 version 过期返回当前 version 元数据，客户端先刷新，不静默覆盖用户修改。操作重试复用原消息，禁止新增重复回答；生成提交前再次验证版本、所有者与取消状态。

版本化约定：破坏性字段修改升 API 版本；增加兼容字段可留 v1。接口与模型/schema/前端 types 的变更必须同批更新文档及契约测试。设计文档中的示意 JSON 不是现有接口返回样本。
